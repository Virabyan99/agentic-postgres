# 0059 — A route boundary is a segment boundary, and the obvious spelling is not one

Status: accepted
Date: 2026-08-11
Session: 5, Run 6
Affects: SEC-API-001, API-REST-001, SEC-DOCS-001, DEP-EDGE-001

## Context

Session 5 puts two new routes on a hostname that already carries one. Until now
the only project router matched `Path(`/__apg/healthz`)` — an exact path, so
there was no boundary to get wrong. The REST surface is a prefix: everything
under `/api/rest` belongs to PostgREST, and nothing else does.

The obvious rule is ``PathPrefix(`/api/rest`)``. Measured against the locked
Traefik:

| request | `PathPrefix(`/api/rest`)` | `Path(`/api/rest`) \|\| PathPrefix(`/api/rest/`)` |
|---|---|---|
| `/api/rest` | 200 | 200 |
| `/api/rest/` | 200 | 200 |
| `/api/rest/notes` | 200 | 200 |
| `/api/restaurant` | **200** | 404 |
| `/api/rest-extra` | **200** | 404 |
| `/api/rest2` | **200** | 404 |

**`PathPrefix` is a string prefix, not a segment prefix.** A router written the
obvious way captures every sibling path that happens to begin with the same
characters.

What that costs is not hypothetical here. `api.public_base_path` is an operator
value, and the reserved-path machinery in `config.RESERVED_BASE_PATHS` refuses
overlaps *segment-wise* (ADR 0005) — so the manifest layer already believes
`/api/rest` and `/api/restaurant` are different routes, while the edge would
have served both from one. Two components disagreeing about what a path
boundary is, with the permissive one at the front.

## Decision

**Every prefix route is ruled as a pair: the exact path, or a child of it.**

```
Host(`…`) && (Path(`/api/rest`) || PathPrefix(`/api/rest/`))
```

The trailing slash in the `PathPrefix` is what makes it a segment boundary, and
the `Path` alternative is what keeps the bare path routable. Both halves are
required: `PathPrefix(`/api/rest/`)` alone 404s `/api/rest`, which is the URL the
deployed document publishes.

A contract test asserts the shape offline, and `test_edge_behaviour.py` asserts
the outcome against a running Traefik — **including a control router ruled the
naive way**, which must over-match. Without the control, the negative
assertions are satisfied by any rule that happens to 404, including a broken
one.

## Consequences

**This applies to the documentation route too**, and to every prefix route a
later session adds. It is written here as a rule about route boundaries rather
than as a fact about one router, because the next one will be written by
copying an existing rule and the existing ones will now all be pairs.

**`Path` and `PathPrefix` are the only two matchers used.** Traefik offers
`PathRegexp`, which could express the same boundary in one term. It is not used:
a regular expression in a router rule is a second place where an anchoring
mistake produces a route that serves more than it names, and the failure mode of
a missing `$` is exactly the failure mode this ADR exists to close.

**The rule is longer than the health route's, and Traefik's default router
priority is rule length.** That is in the right direction — a more specific
route outranks a less specific one — but it is a consequence of the syntax
rather than a decision, so nothing depends on it. No router in this repository
sets an explicit priority, and if one ever needs to, that is a decision to make
deliberately rather than to inherit from how a rule happens to be spelled.

## Alternatives considered

**Trust `PathPrefix` and reserve the sibling paths.** `RESERVED_BASE_PATHS`
could refuse a manifest whose base path is a prefix of another. Rejected: it
constrains the paths this repository derives and says nothing about the ones an
operator writes, and it puts the fix in the layer that was already right rather
than in the layer that was wrong.

**`PathRegexp(`^/api/rest(/.*)?$`)`.** One term, correct, and measured to work.
Rejected on the grounds above — and because the rule is generated by string
substitution into a label value, where a base path containing a regex
metacharacter would change what the expression means. `Path` and `PathPrefix`
take a literal.

**Leave it, because nothing currently serves `/api/restaurant`.** Rejected. The
route boundary is what makes "the REST surface is exactly this schema" a
statement about the edge as well as the database, and a boundary that is correct
because no neighbour exists yet stops being correct the first time one does —
silently, in a session that is not thinking about routing.
