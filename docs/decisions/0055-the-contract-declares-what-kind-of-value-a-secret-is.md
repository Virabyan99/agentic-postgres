# 0055 — The contract declares what kind of value a secret is

Status: accepted
Date: 2026-08-11
Session: 5, Run 3
Extends: [0036](0036-the-provider-bootstrap-seeds-what-the-contract-declares.md)
Affects: SEC-BOOT-001, SEC-DOCS-001

## Context

ADR 0036 made `secrets.required.yaml` the authority for what the provider
bootstrap creates, after D66: bootstrap wrote one secret by name, Session 3's two
credentials existed nowhere, and the first host command failed with a provider
404.

What bootstrap creates is `secrets.token_hex(32)` for every declared secret,
because until now every declared secret was a password. Session 5 declares one
that is not: the bootstrap issuer's RSA private key.

A 64-character hex string stored under `bootstrap_jwt_signing_key` would satisfy
every check this repository has. The contract would validate, bootstrap would
report success, materialization would write the file at `0400` root, the
generation manifest would record it, and the failure would surface several runs
later as PostgREST refusing a JWKS derived from something that is not a key —
with nothing between the cause and the symptom naming the wrong value.

That is this project's defect exactly: a value that looked measured and was not,
green for as long as its wrong answer coincided with the right one.

## Decision

**Every secret declares its `value_kind`, and bootstrap generates accordingly.**

- `random_hex` — 32 bytes from `secrets.token_hex`. What every existing secret
  is, stated rather than assumed.
- `rsa_private_pem` — a 2048-bit RSA private key in PKCS#8 PEM, generated by
  `openssl genpkey`. Multi-line, stored verbatim, materialized verbatim.

`value_kind` is **required on every secret**, for the reason `plane` and
`one_time_initialization` are: a new secret has to state which kind it is, and a
default is how the wrong generator runs.

**A PEM, not a JWK.** The private key's storage form is the one openssl produces
and consumes, so signing needs no conversion and no third-party parser. The
public JWKS PostgREST receives is *derived* from it by root tooling — one stored
value, one derivation — rather than a second stored copy that can drift from the
first. `src/agentic_postgres/jwt_keys.py` does the derivation and refuses any
public JWK carrying a private parameter (ADR 0051).

**Key generation runs through `openssl`, not through a Python library.** The
privileged host path runs on the system interpreter, and `cryptography` is not in
the hash-locked dev toolchain and would not be on the host if it were. openssl is
present on the host and in every locked image, and this repository's answer to
"we need a tool the stdlib does not have" is a measured external one rather than
an unmeasured import.

## Consequences

**Bootstrap can no longer create a secret it does not understand.** An unknown
`value_kind` is refused at contract load, so adding a secret of a new kind is a
deliberate change to the generator rather than a silent fall-through to
`token_hex`.

**Rotation is per-kind and unchanged in shape.** `rotate_by_replacement` still
means what it meant; what the replacement *is* now comes from the same field the
creation did, so a rotated signing key is a new key rather than a hex string.

**The stored form is the signing form.** Anything that signs a token reads this
PEM and hands it to `openssl dgst -sha256 -sign`. There is no path that
reconstructs a key from parts, which is the path that would need the private JWK
parameters this repository has no vetted parser for.

**`value_kind` is not a secret.** It is a shape, it is committed, and it tells a
reader of the contract what a leaked file would contain — which is information
they already have from the name. It buys the generator a decision it was
otherwise making by omission.

## Alternatives considered

**Add `cryptography` to `requirements-dev.in`.** Rejected on where the code runs:
the privileged path uses the host's system interpreter, not the repository's
virtual environment, so a locked dev dependency would be absent exactly where key
generation happens. Installing it on the host is a second provisioning input
whose version nothing here measures.

**Store the key as a private JWK.** Rejected: producing one from openssl means
parsing `openssl rsa -text` for six private parameters, and consuming one means
reassembling a key from them. Both are hand-written handling of private key
material to gain a format that only the public half needs.

**Keep `token_hex` for everything and special-case the one name in bootstrap.**
Rejected. It is the shape ADR 0036 was written to remove — a generator that knows
things the contract does not say — and the special case would be invisible to
every reader of `secrets.required.yaml`, which is the file that exists to make
the secret surface reviewable.
